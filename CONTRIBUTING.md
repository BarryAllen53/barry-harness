# Contributing to Barry Harness

Thanks for your interest in improving Barry Harness. This guide covers how to report problems, propose changes and get a pull request merged.

By participating you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md). Security issues go through [SECURITY.md](SECURITY.md), never through public issues.

## Issues

- Search the existing issues first.
- Use the **Bug report** or **Feature request** form. For bugs, include the Barry Harness version or commit, the Windows version, the provider and model, and the steps to reproduce.
- Remove API keys, tokens, client secrets and personal data from logs and screenshots before you post them.

## Development setup

1. Install [rustup](https://rustup.rs) and the Visual Studio C++ build tools. The toolchain, components and the `wasm32-unknown-unknown` target are pinned in `rust-toolchain.toml` and installed on first use.
2. Install the tools used by the build and the gates:

   ```powershell
   cargo install --locked trunk@0.22.2 cargo-machete@0.10.1 cargo-deny@0.22.1
   ```

3. Run the app in development mode with `run.bat`, or with `cargo tauri dev` if the Tauri CLI 2.12 is installed.

## Quality gates

Every pull request must pass:

```powershell
trunk build --locked
cargo xtask check
```

`cargo xtask check` runs these gates in order and stops at the first failure, printing `gate failed: <name>`:

1. `cargo fmt --check`
2. `cargo clippy --locked --workspace --all-targets -- -D warnings`
3. `cargo xtask lint-comments`
4. `cargo machete`
5. `cargo deny --locked check`

CI also runs clippy for the frontend on `wasm32-unknown-unknown`:

```powershell
cargo clippy --locked --package bh-frontend --target wasm32-unknown-unknown -- -D warnings
```

The `cargo xtask` alias runs with `--locked`, so a stale `Cargo.lock` fails instead of being rewritten. When a new dependency brings a license that is not yet allowed, `cargo deny` fails and the license has to be added to `deny.toml` deliberately, with a note in the pull request.

## Code style

- Formatting follows `rustfmt.toml` (edition 2024, max width 100) and `.editorconfig`.
- Workspace lints forbid `unsafe_code`, warn on unused crate dependencies and enable the clippy `pedantic` group. Every crate opts in with `[lints] workspace = true`.
- Pin new dependencies in `[workspace.dependencies]` of the root `Cargo.toml` and inherit them with `.workspace = true`.
- Remove code, imports and dependencies that a change leaves unused.
- Handle errors explicitly. No `unwrap` on input from the network, the file system or the user.

### No comments

Code, configuration and markup contain no comments of any kind, including doc comments and commented-out code. Names and structure carry the intent; prose belongs in Markdown files and under `docs/`.

`cargo xtask lint-comments` enforces this. It walks the repository, skipping `target`, `dist` and `docs` at the root, `.git` and `node_modules` at any depth, and the files `tauri-build` regenerates on every build (`src-tauri/gen` and any `autogenerated` directory directly inside a `permissions` directory). It prints `path:line: comment` for every hit and `path: unreadable: <reason>` for files that cannot be read or are not UTF-8, and exits non-zero if there is any.

| Files | Detected |
| --- | --- |
| `.rs` | Line, block and doc comments, using the `rustc` lexer so strings, raw strings and nested block comments are handled exactly. Shebangs and attributes are allowed. Cargo script frontmatter is checked as TOML. |
| `.toml` | `#` outside basic, literal and multi-line strings. |
| `.yml`, `.yaml` | `#` that starts a comment, outside quoted and block scalars. |
| `.css`, `.scss` | `/* */` outside strings and unquoted `url(...)`, plus `//` in `.scss`. |
| `.html`, `.svg` | `<!-- -->` outside attribute values, CDATA and raw text elements, plus comments inside scripts, styles and event-handler attributes. |
| `.js`, `.mjs`, `.cjs`, `.ts`, `.mts`, `.cts`, `.jsx`, `.tsx` | `//` and `/* */` outside strings, template literals, regular expression literals and JSX text. |
| `.sh`, `.ps1` | Shell and PowerShell comments outside quotes, here-strings and heredoc bodies. A first-line shebang is allowed. |
| `.gitignore`, `.gitattributes` | Lines starting with `#`. |

A leading UTF-8 byte order mark is ignored in every file type.

## Commits and pull requests

- Branch from `main` and keep each pull request focused on one change.
- Write commit messages in the [Conventional Commits](https://www.conventionalcommits.org) style, for example `fix(bh-openai): keep the account id on refresh`.
- Update `README.md`, `docs/design/` and the `Unreleased` section of `CHANGELOG.md` when behaviour, configuration or the user interface changes.
- Fill in the pull request template. A maintainer listed in `.github/CODEOWNERS` reviews every pull request.
